## 场景、重建与内存

- 两种模型分别下载一份。普通模型实收 13,812,376 B，Meshopt 7,591,900 B。各自识别 196 个稳定标识、26 个静态街区绘制对象，静态阴影各烘焙一次。环境波纹与机械臂的连续采样均有变化。 [双模型记录](render-contracts.json)
- 十轮 API → 工单 → 客服交替各自回到同一组计数：308 个几何体、59 个材质、5 个纹理、1 份模型，章节持有的轨道数为 0。暂停和取消时资源归还。两个模型的抽测锚点与信封位置一致。 [逐轮记录](chat-lifecycle.json)
- 在模型尚未就绪时使用建筑入口选择 FlowOps，下载完成后保留 FO 选择。三次显式重建均记录到一个活动 RAF、13 个当前画布监听器、0 个旧画布监听器、20 个 window/document 监听器。主动丢失上下文后，活动 RAF 与画布监听器归零；站点及浏览器的全局监听器仍有 18 个。 [重建原始记录](phase8-entry.json)
- 三套 story/director、Playback、CameraRig、MotionDirector 共九个文件与 Phase 8 对应文件的 SHA-256 一致。Town 的差异位于加载阶段的接线；实际分支、镜头和资源行为另由浏览器测试核对。 [源码比对](source-comparison.json)

本报告计数取自原测试的运行时、场景遍历与监听登记。GPU 驱动释放时机及物理内存占用并非这些指标的测量对象。真实手机与 Safari 三维需要单独记录。
