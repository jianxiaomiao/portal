## 真机与 Safari

本轮的触屏输入、390px 长图和双端窗口行为来自桌面 Chrome 手机视口。真实 iPhone 的 Safari、Android 的 Chrome、桌面 Safari 的 WebGL 运行仍待实测。本机 Safari 26.6.2 的 WebDriver 未取得自动化会话，具体原因是 Safari 未开启远程自动化。[Safari 探测](hosting/safari.json)

在作者可提供的真机和可访问的隔离 HTTPS 预览上，分别记录型号、操作系统、浏览器、连接、方向、画质、首次启用到可拾取耗时。复核下列访问路径。

1. 手机直接打开首页、软件详情、Studio 与收藏页，竖屏滚动和返回，放大字体后仍可读。确认默认只见海报。
2. 点探索入口。沿画布上滑应滚动页面；开始操控后单指旋转、双指缩放、结束操控后继续阅读。复核旋转设备、系统返回、安全区和弱网进度。
3. 同一设备先从项目页进建筑，再由 Studio 进入室内、由 Creative 进入雪景球。切换夜色后退、重进，核对用户主题及同地点镜头。
4. 三章各走一段分步路径，并在客服章切换客户与坐席。记录切页前后的业务步骤和阅读水位。减少动态模式下试首访、入场跳过、后台切换和恢复。
5. 让标签页暂时进入后台、触发设备内存压力，再返回探索；重试或海报目录可达。分别测一次 Meshopt 与普通 GLB。记录原始结果后再判断是否调整默认画质。

## 生产发布交接

本机已分别生成根域和 /portal/ 前缀产物，后者在本机 Nginx 下模拟 GitHub Pages 路径。真实 Pages 的响应头、CDN 命中和公网速度只能在获准发布后观测。

- 实施成果保存在本地隔离开发分支，当前为未提交改动。审阅时可对照[修改清单](changes.md)和报告中的原始数据。
- 发布前确认域名/仓库可见性、作者资料、移动端已知边界和最终构建前缀。选择 Pages 时注意现有 main 推送自动发布机制。
- 在得到发布授权后使用同一次构建的 HTML、JS、CSS、模型、布局与图片。Nginx 可让带内容指纹的资源长期缓存，HTML 使用条件验证；保留上一份完整产物及旧资源，以覆盖旧标签页的懒载窗口。回退以整套产物为单位。
- 首次上线再从外部网络实测首页响应、独立地址刷新、404、两模型、无 WebGL 路径和缓存头。真实生产测试记录与本机数据分开保存。
