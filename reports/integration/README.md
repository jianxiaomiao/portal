# 模型加载、导航与资源生命周期实测

测试对象为本机 Portal 的诊断生产构建。公开生产包单独接受了两种路径、两种模型和静态降级测试。运行时取自同一套源码，诊断构建仅增加持有对象、镜头、状态、时钟与资源计数的测试接口。

## 冷载与海报首屏

桌面 Chrome 158，1440 × 900，DPR 1。CDP 模拟下行 10 Mbit/s、上行 5 Mbit/s、80 ms 延迟。每种模型各测三轮，每轮使用新上下文，禁用浏览器资源缓存并交替执行两种模型。先加载默认的静态首页，等页面 load 后自动点击“启用三维预览”。计时从该次点击到 Town 初次渲染并建好拾取器。操作系统缓存、GPU 缓存及本机负载未隔离。

| 候选资源 | GLB 实际 body | 从启用到就绪，中位数 [最小–最大] | 路径 |
| --- | ---: | --- | --- |
| 普通 GLB | 13,812,376 B | 13.69 s [13.59–13.86] | ?model=raw，三轮均只取普通模型 |
| Meshopt | 7,591,900 B | 8.52 s [8.33–9.28] | 候选默认，额外请求按需解码模块 |

这六次访问中，首页 h1 和主导航链接均在导航后约 99–120 ms 进入 DOM，首次内容绘制约为 268–364 ms；点启用前 GLB 请求数为 0。这些时间分别描述结构可用、内容绘制和三维交互。此前 Phase 8 的 36 次对照中，10 Mbit/s 下的 12.96 s、8.05 s 从三维页导航开始计时，二者起点不同。[逐次传输、解码、首绘与阶段数据](loading.json)

已记录压缩路径的接收模型、准备解码器、解析场景、准备首帧、启用选取五个实际阶段。普通版直接进入解析。另以带分块传输、无 Content-Length 的回环服务器停在 256 KiB，UI 显示已收 0.3 MiB，progress 没有确定百分比；恢复传输后正确收到完整 7,591,900 B。[分块与解析取消](loading-edges.json)

## 实例与资源所有权

| 用例 | 实测结果 |
| --- | --- |
| 十轮首页主动启用 → 完整探索 → 返回普通首页 | 每轮只发出一次 GLB 请求。提升前后 canvas 和 ENV.Root 的 JS 引用完全相同，modelCount = 1。释放后无活动 canvas，原 canvas 离开文档且 WebGL context 已释放，场景 RAF = 0。十轮全部满足。 |
| 在途请求竞争 | 一次连续双击启动、未收齐 GLB 时进入探索再离开。只有一个下载者；延迟响应结束后首页保持海报、canvas 为 0。 |
| 在解析阶段离开 | 通过浏览器原生 createImageBitmap 延迟两个真实纹理位图的返回。离开后放行，两个位图均收到 close，旧结果没有创建 canvas 或重新挂上宿主。 |
| 压缩模型/解码器故障 | 分别阻断压缩 GLB 和解码模块，均只回退普通版一次并就绪。两版均不可用时保留静态目录；损坏共享 layout 时只有一次压缩模型请求。 |
| 三次场景完整重建 | 各轮旧画布持久监听数为 0，当前画布监听和活动 RAF 回到初始数量。实际触发 WEBGL_lose_context 后，当前画布持久监听与场景 RAF 均为 0。 |
| 十轮三章交替 | 每轮仅一章持有场景；章末回到同构建稳态 308 几何 / 59 材质 / 5 纹理 / 1 模型，章节占有轨道为 0。这组计数用于同机同构建往返对照。 |
| 缓存 | 两个 Nginx 前缀下，常规 Chrome 用户配置对同版本 Meshopt 第二次请求 transferSize 为 0，CDP 确认命中磁盘。浏览器上下文、驱逐与服务器响应会影响跨文档缓存。跨文档重建仍需重新解析和创建 GPU 对象。 |
